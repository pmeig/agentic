# Lead playbook: parallelism and extra agents

- Use token-aware parallelism for **every agent role**: launch as many agents simultaneously as are useful when each has independent, clearly bounded work and the expected time/quality gain justifies the marginal token/context/tool cost. There is no fixed maximum number and no default limit of two. Split `front`, `back`, `qa`, `designer`, `translator`, `documentalist`, `sales`, or other specialist work when work packages are genuinely independent; assign disjoint file ownership where editing files. Before each additional launch, assess expected marginal benefit versus cost, avoid duplicated context/scans and overlapping edits, and stop adding agents when marginal benefit no longer justifies the cost. Keep dependencies and gates sequential (e.g. user must choose a mockup before implementation; shared contracts must be agreed before coding; QA go before docs; docs before push).
- `front` and `back` may each be split across multiple agents when work can be divided into disjoint paths with explicit owners (for example, front state/helpers vs page components, or separate backend modules). Before each extra spawn, record the bounded task, file ownership, why it can proceed independently, expected wall-time saved and token/context cost risk in `state.md`. Start with one owner for small tasks; two parallel owners are the default for a large, separable package; add a third only when there is still independent work and the marginal speedup is worth the extra context. Never assign the same file to two agents. Shared contract changes are agreed first; do not parallelize sequential gates. Reuse short cold-start briefs, avoid duplicated scans/images, and keep logs quiet.
- After work, measure actual token usage with `python scripts/claude-token-usage.py`; report per-transcript counts and note that usage reports are not estimates or billing totals. Do not invent exact usage estimates.
